# 📚 Теоретична база (Knowledge Base)

## Лабораторна робота №5: Використання Java Database Connectivity для роботи з базами даних

---

### 1. Що таке JDBC та для чого потрібен JDBC-драйвер?
**JDBC (Java Database Connectivity)** — це стандартний Java API, який дозволяє Java-застосункам взаємодіяти з різними реляційними базами даних (MySQL, PostgreSQL, H2 тощо).

**JDBC-драйвер** — це програмний компонент (бібліотека), який слугує \"перекладачем\". Оскільки кожна база даних має свій власний протокол зв'язку, драйвер перетворює універсальні Java-виклики JDBC у специфічні команди, які розуміє конкретна БД.

---

### 2. Типи JDBC-драйверів
Існує 4 основні типи драйверів:
1.  **Type 1: JDBC-ODBC Bridge** — використовує ODBC драйвери Windows (застарілий).
2.  **Type 2: Native-API Driver** — використовує клієнтські бібліотеки бази даних (C/C++).
3.  **Type 3: Network-Protocol Driver** — використовує проміжний сервер (middleware).
4.  **Type 4: Native-Protocol All-Java** — найпопулярніший. Спілкується безпосередньо з БД через сокети. Повністю написаний на Java.

---

### 3. Переваги PreparedStatement у порівнянні зі звичайним Statement
`PreparedStatement` є розширенням `Statement` і надає наступні переваги:
* **Безпека:** Автоматично екранує вхідні параметри, запобігаючи SQL-ін'єкціям.
* **Продуктивність:** Запит компілюється базою даних лише один раз (Pre-compilation). При повторних викликах з іншими параметрами БД використовує вже готовий план виконання.
* **Чистота коду:** Замість конкатенації рядків (`\"WHERE id = \" + id`) використовуються плейсхолдери (`?`).

---

### 4. Різниця між методами execute(), executeQuery() та executeUpdate()
| Метод | Коли використовувати | Що повертає |
| :--- | :--- | :--- |
| `executeQuery()` | Для запитів `SELECT`. | `ResultSet` (набір рядків з бази). |
| `executeUpdate()` | Для `INSERT`, `UPDATE`, `DELETE` або DDL запитів. | `int` (кількість змінених рядків). |
| `execute()` | Коли тип запиту невідомий заздалегідь. | `boolean` (`true` для ResultSet, `false` для count). |

---

### 5. Що таке SQL-ін'єкція? Як від них захиститися?
**SQL-ін'єкція** — це тип атаки, при якій зловмисник вставляє шкідливий SQL-код у поля введення, намагаючись змінити логіку запиту або отримати несанкціований доступ до даних.

## Лабораторна робота №6: Використання Java Persistence API для роботи з базами даних

### 1. Що таке JDBC та для чого потрібен JDBC-драйвер?
**JDBC (Java Database Connectivity)** — це стандартний Java API, призначений для універсальної взаємодії Java-застосунків із різними реляційними базами даних.

**JDBC-драйвер** — це програмна бібліотека, яка реалізує інтерфейси JDBC для конкретної СУБД (наприклад, PostgreSQL або MySQL). Він виступає у ролі «перекладача», конвертуючи універсальні виклики Java у специфічні команди, які здатна зрозуміти конкретна база даних.

---

### 2. Які типи JDBC-драйверів ви знаєте?
Виділяють чотири основні типи драйверів:
*   **Type 1 (JDBC-ODBC Bridge):** використовує драйвери ODBC Windows для підключення до бази (застарілий тип, майже не використовується).
*   **Type 2 (Native-API):** використовує клієнтські бібліотеки бази даних, написані мовами C/C++.
*   **Type 3 (Network-Protocol):** спілкується з проміжним сервером (middleware) за допомогою спеціального мережевого протоколу.
*   **Type 4 (Native-Protocol All-Java):** спілкується безпосередньо з БД через сокети; повністю написаний на Java (найпоширеніший та найшвидший тип).

---

### 3. Які переваги надає PreparedStatement у порівнянні зі звичайним Statement?
`PreparedStatement` має наступні ключові переваги:
*   **Безпека:** автоматично екранує вхідні параметри, що забезпечує надійний захист від атак типу **SQL-ін’єкція**.
*   **Продуктивність:** запит компілюється базою даних лише один раз; при повторних викликах з іншими параметрами БД використовує вже готовий план виконання.
*   **Зручність:** використання плейсхолдерів (`?`) замість складної та помилкової конкатенації рядків.

---

### 4. Різниця між методами execute(), executeQuery() та executeUpdate() класу PreparedStatement
| Метод | Призначення | Що повертає |
| :--- | :--- | :--- |
| **`executeQuery()`** | Тільки для запитів `SELECT`. | Об'єкт `ResultSet` (набір даних). |
| **`executeUpdate()`** | Для запитів `INSERT`, `UPDATE`, `DELETE` або DDL. | Кількість змінених рядків (тип `int`). |
| **`execute()`** | Універсальний метод для будь-яких запитів. | `boolean` (`true` для ResultSet, `false` для кількості змін). |

---

### 5. Яким вимогам має відповідати JPA Entity?
Клас сутності (Entity) повинен відповідати таким критеріям:
*   Мати обов'язкову анотацію **`@Entity`**.
*   Мати **порожній конструктор** (без параметрів) з рівнем доступу `public` або `protected`.
*   Мати поле, позначене як **первинний ключ (`@Id`)**.
*   Клас не може бути фінальним (**final**).
*   Поля сутності не повинні бути `public` (доступ здійснюється через getter/setter методи).

---

### 6. В чому полягає різниця між анотаціями @Id та @EmbeddedId?
*   **`@Id`**: використовується для оголошення **простого** первинного ключа, який складається з одного поля.
*   **`@EmbeddedId`**: використовується для оголошення **складеного** (composite) первинного ключа. У цьому випадку поля ключа виносяться в окремий клас, який позначається анотацією `@Embeddable`.

---

### 7. Які операції над сутностями можна виконувати за допомогою EntityManager?
Основні методи керування життєвим циклом об'єктів у `EntityManager`:
*   **`persist(entity)`**: додавання нової сутності до бази даних (стан managed).
*   **`find(Class, id)`**: пошук сутності в базі за її первинним ключем.
*   **`merge(entity)`**: оновлення стану сутності, яка була від'єднана (detached) від контексту.
*   **`remove(entity)`**: видалення сутності з бази даних.
*   **`createQuery()`**: створення динамічного запиту для отримання списку об'єктів.

---

### 8. Чим JPQL відрізняється від SQL?
*   **SQL** працює безпосередньо з фізичними **таблицями та колонками** в базі даних.
*   **JPQL (Jakarta Persistence Query Language)** працює з **Java-об'єктами (Entities) та їхніми атрибутами**. Замість `SELECT * FROM users` ми пишемо `SELECT u FROM User u`. Hibernate автоматично конвертує JPQL у SQL-діалект вашої бази даних (наприклад, PostgreSQL).

---

### 9. В чому полягає різниця між Query та NamedQuery?
*   **Query**: динамічний запит, який створюється безпосередньо в коді програми за допомогою `em.createQuery()`. Використовується, коли логіка запиту залежить від умов під час виконання програми.
*   **NamedQuery**: статичний запит, який оголошується заздалегідь за допомогою анотації над класом сутності. Такі запити компілюються один раз при запуску застосунку, що підвищує продуктивність і дозволяє використовувати їх повторно в різних частинах коду.
